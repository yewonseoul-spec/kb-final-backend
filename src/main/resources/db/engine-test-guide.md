# 추천 엔진 시연 가이드

> 최종수정: 2026-08-07
> 시연용 프로필, 진행 순서, 조작할 때마다 나올 결과와 그 이유를 정리했다.
> 필터링 동작의 근거는 「engine-filtering.md」 참고.

---

## 1. 시연 프로필 (고정)

**회원 2번을 아래 값으로 맞춘다.** 값이 다르면 결과가 달라져 설명과 화면이 어긋난다.

| 항목 | 값 |
| --- | --- |
| 생년월일 | 1998-03-03 (만 28세) |
| 거주지역 | 경기도 수원시 장안구 (`41111`) |
| 소득 | 2,074,000 (월) |
| 취업상태 | 재직자 |
| 전공 | 인문계열 |
| 학력 | 고졸 미만 |
| 혼인 여부 | 미혼 |
| 가구원 수 | 3 |

### 기준 결과

```
자격 조건 통과      20개
추천 조합           3개
  ① (문체부) 청년예술인 예술활동 적립계좌
  ② 청년 국가기술자격 응시료 지원 사업
  ③ 청년키움지원센터 운영
경고
  일부제한 · 청년주택드림청약통장
  다른 제도 · 청년미래플러스
```

**보유 정책 2건**이 등록되어 있어야 한다.

```
햇살론유스 (G01)
평택시 우수초기창업자 지원사업 (G02)
```

없으면 `engine_test_data.sql`을 실행한다. **보유 정책이 없으면 중복수혜 검사가 아무것도 걸러내지 못한다. 비교할 대상이 없기 때문이다.**

## 2. 시연 순서

### ① 프로필 보여주기 · 30초

마이페이지 → 프로필

> 이 사람은 경기도 수원시 장안구에 사는 만 28세 재직자입니다. 월소득 207만원이고요.
> 이 일곱 개 조건으로 정책을 거릅니다.

**여기서 시작하는 이유** — 뒤에 나오는 숫자가 어디서 왔는지 근거가 생긴다. 결과부터 보여주면 "그래서 이게 뭔데?"가 된다.

---

### ② 결과 · 40초

홈 → 배너 → AI 정책 조합 최적화

> 2,700개 중 자격이 되는 게 **20개**, 그중 함께 신청할 수 있는 조합이 **3개**입니다.

'적용된 조건 보기'를 펼친다.

> 연령·취업·학력·전공·혼인·지역이 모두 걸렸습니다. 소득은 조건이 명시되지 않은 정책이라 확인이 필요하다고 표시됩니다.

---

### ③ 경고 · 40초

화면 아래 '함께 신청할 때 확인하세요'로 내려간다.

> 못 받는 걸 전부 지우지는 않습니다. **규정상 아예 안 되는 것만 조용히 빼고**, 받을 수는 있지만 주의할 건 알려줍니다.
>
> 청약통장은 햇살론유스를 상환 중이면 연계 대출의 우대 조건이 제한됩니다.
> 실업급여를 받는 중이면 청년미래플러스도 제한될 수 있고요.

**이 부분이 설계의 핵심이다.** 시스템이 판단을 대신하지 않고 사용자에게 넘긴다.

---

### ④ 실시간 변화 · 60초 ★ 하이라이트

마이페이지 → 신청 혜택 → **청년주택드림청약통장 등록** → 엔진으로 복귀

**예상 결과**

```
20개  →  19개
청약통장이 목록에서 사라짐
경고 2줄  →  1줄 (일부제한 없어짐)
```

> 청약통장을 신청했다고 등록했습니다. 그랬더니 목록에서 빠졌고, **그 정책에 붙어 있던 경고도 함께 사라졌습니다.**

**⚠️ 시연 전에 이 흐름을 한 번 돌려볼 것.** 새로고침 없이 갱신되는지, 뒤로가기로 돌아갈지 탭바로 돌아갈지 미리 정해둔다.

---

### ⑤ 지역 바꾸기 · 60초 (선택)

여유가 있으면 조건 하나가 결과를 얼마나 바꾸는지 보여준다.

마이페이지 → 지역을 **경기도**로 변경 → 엔진 복귀

**예상 결과**

```
19개  →  38개   (청약통장 등록 상태 유지 시)
경고 1줄  →  3줄
```

> 지역만 광역으로 바꿨는데 후보가 두 배가 됐습니다.

**끝나면 반드시 장안구로 되돌린다.**

---

### ⑥ 마무리 · 30초

> 신청하고 나서 반려당하거나 환수당하는 걸 미리 막아주는 것, 이게 차별점입니다.
>
> 다만 이 규칙은 온통청년이 제공하지 않아서 **관리자가 공고문을 읽고 직접 등록합니다.** 지금은 시연용 11건이고, 검수를 마친 7건만 적용됩니다.

## 3. 조작별 예상 결과와 이유

### 청약통장을 신청 혜택에 등록

| | 전 | 후 |
| --- | --- | --- |
| 후보 | 20 | **19** |
| 경고 | 2줄 | **1줄** |

**왜 후보가 줄어드나**

```sql
AND b.benefit_no NOT IN (
  SELECT benefit_no FROM applied_benefit WHERE member_no = #{memberNo}
)
```

이미 받고 있는 정책은 다시 추천하지 않는다.

**왜 경고까지 사라지나**

경고는 **"내가 받는 것 ↔ 앞으로 받을 것"** 관계에 붙는다. 청약통장이 '앞으로 받을 것'에서 '이미 받는 것'으로 넘어가면, 그 관계 자체가 성립하지 않는다.

경고를 지우는 코드를 따로 만든 게 아니라 **비교 대상이 없어져서 자연히 사라지는 것**이다.

---

### 지역을 경기도(`41000`)로 변경

| | 장안구 | 경기도 |
| --- | --- | --- |
| 후보 | 20 | **39** |
| 경고 | 2줄 | **4줄** |
| 추가로 나타나는 경고 | | 확인필요 · 학자금대출 장기연체자<br>다른제도 · 안성시 청년내일캠프 |

**왜 두 배가 되나**

온통청년은 정책 지역을 **항상 최하위 행정구역으로 펼쳐서** 준다. `benefit_region`에는 시군구 코드만 있고 `41000 경기도` 같은 광역 코드로 저장된 행은 없다.

엔진은 계층을 **두 단계까지** 비교한다.

| 회원 지역 | 걸리는 정책 |
| --- | --- |
| 41111 장안구 | 장안구 + 수원시 + 경기도 + 전국 |
| 41000 경기도 | **경기도 모든 시군구** + 전국 |

장안구를 고르면 **군포시·안성시 정책은 안 걸린다.** 같은 경기도라도 시가 다르기 때문이다.

경기도를 고르면 경기 전역이 들어와서 두 배가 된다.

**왜 경고가 늘어나나**

- 확인필요 규칙은 **군포시** 정책(학자금대출 장기연체자)에 걸려 있다
- 외부제도 규칙 하나는 **안성시** 정책(청년내일캠프)에 걸려 있다

장안구에서는 두 정책이 후보에서 빠지므로 규칙이 등록되어 있어도 화면에 나올 자리가 없다. **규칙이 사라진 게 아니라 대상이 없는 것이다.**

---

### 지역을 안성시(`41550`)로 변경

| | 결과 |
| --- | --- |
| 후보 | 20 안팎 |
| 경고 | **3줄** |

안성시 청년내일캠프가 살아나면서 외부제도 경고가 복귀한다. 군포시 정책은 여전히 빠진다.

---

### 소득을 바꾸면 — 거의 변화 없다

**보여주지 않는 것을 권한다.**

소득 조건이 세 종류인데, 실제로 숫자를 비교하는 건 `0043002` **약 30건뿐**이다.

| 코드 | 처리 | 건수 |
| --- | --- | --- |
| `0043001` 제한없음 | 무조건 통과 | 대부분 |
| `0043003` 기타(자연어) | 판정 불가 → 통과 | 약 328건 |
| `0043002` 연소득 기준 | **숫자로 비교** | 약 30건 |

전체의 1%라 소득을 크게 바꿔도 후보 수가 거의 안 움직인다.

---

### 생년월일을 바꾸면 — 효과는 크지만 권하지 않는다

연령 조건이 있는 정책이 대부분이라 후보가 급감한다. 다만

- 40대로 바꾸면 화면이 거의 비어 보인다
- 되돌리기가 번거롭다
- 의료비 기대값 등 다른 계산에도 영향이 간다

---

### 취업·학력·전공을 바꾸면 — 변화 폭이 작다

매핑 행이 아예 없는 정책은 **제한이 없는 것으로 보고 통과**시킨다. 실제로 매핑이 있는 정책이 적어서 값을 바꿔도 티가 잘 안 난다.

## 4. 예상 질문

### "수원 사람인데 왜 경상북도 의성군 정책이 나오나요?"

후보 20개 중 6개가 의성군 정책이다. 추천 ③번도 의성군이다.

> 온통청년이 지역 정보를 주지 않는 정책이 있습니다. 그런 정책은 **전국 대상으로 보고 통과**시키는데, 실제로는 특정 지자체 정책인 경우가 섞여 있습니다.
>
> 걸러내면 진짜 전국 정책까지 놓치기 때문에 지금은 통과시키는 쪽을 택했고, **데이터 품질 개선이 필요한 부분**입니다.

### "중복불가인 정책 두 개를 둘 다 신청했다고 등록하면요?"

> 지금은 **추천 대상만 검사**합니다. 이미 받고 있는 정책끼리는 비교하지 않아서 아무 경고도 뜨지 않습니다.
>
> 실제로는 둘 다 받을 수 없으니 발생하면 안 되는 상황이지만, 사용자가 직접 입력하는 값이라 잘못 등록할 수 있습니다. **등록 시점에 확인을 받는 것이 다음 단계**입니다. 막지는 않을 계획입니다. 사용자가 실제로 받고 있는 사실을 시스템이 막으면 데이터가 거짓이 되기 때문입니다.

### "이 중복수혜 규칙은 어디서 가져온 건가요?"

> 온통청년 API는 정책 간 관계를 제공하지 않습니다. **정책의 지원 내용과 주관기관을 직접 읽고** 같은 목적의 자금 지원이거나 동시 이용이 불가능한 쌍만 등록했습니다.
>
> 다만 각 기관이 실제로 고시한 규정임을 확인한 것은 아니라서, 일부는 **검수필요 상태로 남겨** 관리자 검수 대기를 재현했습니다.

### "추천 3개가 최적인가요?"

> 상위 20개로 추린 뒤 조합하기 때문에 **전역 최적은 아닙니다.** "선별된 후보군 안에서의 최적"이 정확한 표현입니다.
>
> 그리고 정렬 1순위가 정책 수라서 3개짜리 조합이 있으면 항상 3개짜리가 선택됩니다.

### "왜 금액이 큰 정책을 우선하지 않나요?"

> `support_amount` 컬럼은 있지만 온통청년이 값을 주지 않아 전부 비어 있습니다. 그래서 **인기도·자격 확실성·시급성**으로 점수를 냅니다.

## 5. 시연 전 점검

- [ ] 회원 2번 프로필이 위 값과 같은가
- [ ] 보유 정책 2건이 등록되어 있는가
- [ ] 엔진 화면에 **20개 · 추천 3개 · 경고 2줄**이 나오는가
- [ ] 청약통장 등록 → 19개 · 경고 1줄로 바뀌는가
- [ ] 등록 후 새로고침 없이 갱신되는가, 아니면 F5가 필요한가
- [ ] 원상복구(청약통장 삭제) 후 20개로 돌아오는가
- [ ] 신청 혜택 화면에서 청약통장을 무슨 검색어로 찾는가

**마지막 항목을 꼭 확인한다.** 시연 중 검색해서 못 찾으면 하이라이트가 끊긴다.
