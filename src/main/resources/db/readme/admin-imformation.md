# 관리자 화면 변경 안내

> 담당: 박상호 · 최종수정: 2026-08-07
> 혜택 관리·동기화 로그 화면에 적용한 내용과 확인 방법을 정리했다.

---

## 한눈에

| 화면 | 바뀐 것 |
| --- | --- |
| 공통 | 하단 탭바 제거 |
| 혜택 관리 | 상태 명칭 정리 · 카테고리 색상 · 컬럼 정렬 |
| 동기화 로그 | 오류 메시지 한글화 · 원문을 상세 모달로 이동 |

---

## 1. 하단 탭바 제거

관리자 화면에 사용자용 하단 탭바가 떠 있었다. 왼쪽에 사이드바가 이미 있어 이동 수단이 겹치고, 누르면 사용자 화면으로 빠져나간다.

라우터 설정 한 줄로 처리했다.

```js
// src/router/admin.js
meta: { requiresAuth: true, requiresAdmin: true, title: '관리자', hideTabBar: true }
```

`App.vue`에 이미 `hideTabBar`를 보는 조건이 있어서 값만 넣으면 된다. 다른 화면에는 영향이 없다.

## 2. 혜택 관리 · 상태 명칭 정리

### 무엇이 문제였나

**같은 단어가 "현재 상태"와 "누르면 할 동작" 양쪽에 쓰이고 있었다.**

```
상태: 숨김   →  버튼: 노출     (누르면 노출됨)
상태: 노출   →  버튼: 숨김     (누르면 숨겨짐)
```

"노출"이 보여도 지금 노출 중인지, 누르면 노출되는 건지 알 수 없다.

### 어떻게 바꿨나

| 자리 | 전 | 후 |
| --- | --- | --- |
| 상태 컬럼 | 노출 / 숨김 | **활성 / 비활성** |
| 관리 버튼 | 노출 / 숨김 | **활성화 / 비활성화** |
| 필터 라벨 | 노출 상태 | 활성 상태 |
| 확인 모달 | 노출을 중단할까요? | 비활성화할까요? |

**상태는 명사, 동작은 `-화`가 붙은 동사로 갈랐다.** DB 컬럼명(`is_active`)과도 맞고, 대시보드의 '추천 가능 정책' 카드와도 뜻이 이어진다.

### 안내 문구 추가

확인 모달에 한 줄 넣었다.

> 다음 동기화에서 온통청년 기준으로 다시 계산될 수 있습니다.

`is_active`는 동기화가 신청기간을 보고 다시 계산한다. 관리자가 비활성으로 내려도 다음 동기화에서 되살아날 수 있어 미리 알린다.

## 3. 혜택 관리 · 카테고리 색상

목록에서 같은 분야가 눈으로 묶이도록 카테고리마다 색을 넣었다.

| 카테고리 | 색 |
| --- | --- |
| 일자리 | 파랑 |
| 주거 | 초록 |
| 교육 | 보라 |
| 복지·문화 | 노랑 |
| 참여·권리 | 청록 |

연한 배경 + 진한 글자 + 같은 계열 테두리라 표가 시끄러워지지 않는다. 상세 모달에도 같은 색이 붙는다.

## 4. 혜택 관리 · 컬럼 정렬

컬럼 헤더를 누르면 그 기준으로 정렬한다.

### 정렬 가능한 컬럼

| 컬럼 | 기준 컬럼 | 오름차순이면 |
| --- | --- | --- |
| 혜택명 | `plcy_nm` | 가나다 ㄱ부터 |
| 주관기관 | `sprvsn_inst_cd_nm` | 가나다 ㄱ부터 |
| 마감 | `apply_end_date` | 임박한 것부터 |
| 조회수 | `inq_cnt` | 적은 것부터 |

**상태·카테고리·중복규칙은 정렬을 넣지 않았다.** 위에 필터가 이미 있어 정렬할 이유가 없다.

### 화살표 읽는 법

```
⇅   정렬 안 함 (기본)
▲   오름차순
▼   내림차순
```

같은 컬럼을 계속 누르면 `⇅ → ▲ → ▼ → ⇅`로 돈다. 세 번 누르면 기본으로 돌아온다.

지금 무엇으로 정렬 중인지는 건수 옆에 나온다.

```
전체 2,704건 · 마감 오름차순
```

### 기본 정렬

아무것도 누르지 않으면 **최신 등록순**이다. (`frst_reg_dt DESC`)
온통청년에 늦게 올라온 정책이 위로 온다.

### 문자 정렬 순서

DB의 유니코드 정렬 규칙(`utf8mb4_0900_ai_ci`)을 그대로 쓴다.

**오름차순 기준**

```
1. 공백
2. 기호·문장부호     [ ] 「 」 ( ) · ~ - _ , . 등
3. 숫자             0 1 2 ... 9
4. 영문             a A b B ... z Z   (대소문자 구분 안 함)
5. 한글             가 나 다 ... 하
```

**주의할 점 세 가지**

**① 숫자는 크기순이 아니라 글자순이다**

혜택명은 문자열이라 첫 글자부터 비교한다.

```
"2026년 청년..."     ← 먼저
"9월 마감 사업..."   ← 나중
```

2026이 9보다 작아서가 아니라, 글자 `2`가 글자 `9`보다 앞이기 때문이다. 같은 이유로 `"10기 모집"`이 `"3기 모집"`보다 앞에 온다.

**② 대소문자를 구분하지 않는다**

`ci`(case insensitive)라 `"AI 전문인력"`과 `"ai 전문인력"`은 같은 값으로 본다. 그럴 때는 혜택번호 내림차순으로 갈린다.

**③ 대괄호로 시작하는 정책이 맨 위로 몰린다**

기호가 숫자·한글보다 앞이라, 혜택명 오름차순을 누르면 이런 정책이 먼저 나온다.

```
[광주 서구] 마음회복×진로설계 특강
[남구] 2026년 청년 자격증 취득 지원
「공공임대주택 청년창업공간」 입주기업 모집
```

온통청년 데이터에 대괄호로 시작하는 정책이 많아 눈에 띈다.

### 마감 정렬은 규칙이 하나 더 있다

**상시 모집과 기간 미정은 어느 방향이든 맨 뒤로 보낸다.**

```sql
ORDER BY apply_end_date IS NULL ASC, apply_end_date ASC
```

날짜가 없는 혜택을 중간에 섞으면 읽기 어렵기 때문이다. 오름차순이면 이렇게 나온다.

```
오늘 마감 → D-1 → D-7 → ... → 상시 모집 / 기간 미정
```

### 왜 서버에서 정렬하나

목록이 2,700건인데 화면에는 20건만 내려온다. **화면에서 정렬하면 그 20건 안에서만 섞여서 "마감 임박순"이 전체 기준이 아니게 된다.** 틀린 결과를 보여주는 셈이라 서버에 맡겼다.

정렬을 걸고 **2페이지로 넘어가도 순서가 이어지면** 서버 정렬이 제대로 동작하는 것이다.

### 순서가 같을 때

정렬 값이 같은 행이 여럿이면 혜택번호 내림차순으로 갈린다. 이게 없으면 페이지를 넘길 때 같은 혜택이 두 번 나오거나 빠질 수 있다.

## 5. 동기화 로그 · 오류 메시지 한글화

### 무엇이 문제였나

실패 로그에 자바 예외 원문이 그대로 떴다.

```
BadSqlGrammarException: ### Error updating database.  Cause: java.sql...
```

**테이블 구조와 SQL 문이 화면에 노출된다.** 관리자가 읽을 수도 없다.

### 어떻게 바꿨나

`src/util/syncError.js`에서 원문을 읽고 한글 요약으로 바꾼다. **원문은 지우지 않고 상세 모달에 접어둔다.** 원인 파악에는 필요하기 때문이다.

**이미 한글인 메시지는 건드리지 않는다.** 한글 4자 이상이고 예외 흔적이 없으면 그대로 통과시킨다.

### 대응표

**DB 제약**

| 원문에 들어 있는 것 | 화면 표시 |
| --- | --- |
| `Column 'x' cannot be null` | 필수 값이 비어 있어 저장하지 못했습니다 (x) |
| `Unknown column 'x'` | DB에 없는 항목을 사용했습니다. 스키마가 최신인지 확인하세요 (x) |
| `Table 'x' doesn't exist` | DB에 없는 테이블을 사용했습니다 (x) |
| `Duplicate entry` | 이미 있는 데이터를 다시 저장하려 했습니다 |
| `foreign key constraint` | 참조하는 기준 데이터가 없어 저장하지 못했습니다 |
| `Data too long for column 'x'` | 값이 저장 가능한 길이를 넘었습니다 (x) |
| `Incorrect ... value` | 값의 형식이 맞지 않아 저장하지 못했습니다 |
| `Out of range value` | 숫자 값이 저장 가능한 범위를 넘었습니다 |
| `Check constraint ... violated` | 허용되지 않는 값이라 저장하지 못했습니다 |

**DB 연결**

| 원문 | 화면 표시 |
| --- | --- |
| `CannotGetJdbcConnection` · `Communications link failure` | DB에 연결하지 못했습니다 |
| `Deadlock found` · `Lock wait timeout` | 다른 작업과 겹쳐 DB 처리가 지연되었습니다. 다시 시도해 주세요 |

**외부 API 응답**

| 원문 | 화면 표시 |
| --- | --- |
| `500` · `InternalServerError` | 온통청년 서버에서 오류가 발생했습니다 (HTTP 500) |
| `502` · `503` · `504` | 온통청년 서버가 응답하지 않습니다. 잠시 후 다시 시도해 주세요 |
| `404` · `NotFound` | 요청한 주소를 찾을 수 없습니다 (HTTP 404) |
| `401` · `403` | API 인증에 실패했습니다. 서비스 키를 확인하세요 |
| `429` | 요청이 너무 많아 일시적으로 차단되었습니다 |
| `400` | 요청 형식이 올바르지 않습니다 (HTTP 400) |

**네트워크**

| 원문 | 화면 표시 |
| --- | --- |
| `SocketTimeout` · `timed out` | 응답을 기다리다 시간이 초과되었습니다 |
| `UnknownHost` · `Connection refused` | 외부 서버에 연결하지 못했습니다. 네트워크를 확인하세요 |
| `SSL` · `Certificate` | 보안 연결에 실패했습니다 |

**응답 파싱**

| 원문 | 화면 표시 |
| --- | --- |
| `<!DOCTYPE html` · `<html` | 서버가 정상 데이터 대신 오류 페이지를 보냈습니다 |
| `JsonParse` · `JsonMapping` | 응답 형식을 해석하지 못했습니다 |
| `NumberFormat` · `DateTimeParse` | 응답에 형식이 잘못된 값이 있어 변환하지 못했습니다 |

**코드 오류**

| 원문 | 화면 표시 |
| --- | --- |
| `NullPointerException` | 처리 도중 값이 비어 오류가 발생했습니다 |
| `IndexOutOfBounds` | 응답 데이터 개수가 예상과 달라 오류가 발생했습니다 |
| `ClassCast` · `IllegalArgument` · `IllegalState` | 처리 중 예상하지 못한 값이 들어와 오류가 발생했습니다 |
| `OutOfMemory` | 처리량이 많아 메모리가 부족했습니다 |

**어느 규칙에도 안 걸리면** "알 수 없는 오류가 발생했습니다"로 나오고 원문 보기가 뜬다. **처음 보는 오류가 와도 화면이 깨지지 않는다.**

## 6. 동기화 로그 · 원문을 상세 모달로

### 무엇이 문제였나

표 안에서 원문을 펼치면 **행 높이가 확 늘어난다.** HTML 오류 페이지는 수백 자라 표가 흔들린다.

그리고 **실패한 로그는 '보기' 버튼이 회색이었다.** 처리 건수가 0이라 막아뒀는데, 정작 원인을 봐야 할 로그에서 모달을 못 열었다.

### 어떻게 바꿨나

| | 전 | 후 |
| --- | --- | --- |
| 표 오류 칸 | 요약 + 펼침 | **요약만** |
| 버튼 라벨 | 보기 | 오류가 있으면 **오류**(빨강), 없으면 보기 |
| 버튼 활성 조건 | 처리 건수 > 0 | **오류가 있으면 열림** |
| 모달 이름 | 동기화 갱신 내역 | **동기화 상세** |
| 모달 내용 | 갱신 내역만 | **오류 원문 + 갱신 내역** |

갱신 내역이 없을 때 문구도 갈랐다.

- 실패한 로그 → "동기화가 실패해 처리된 혜택이 없습니다"
- 성공했는데 내역이 없는 로그 → "기간별 동기화만 내역을 남깁니다"

## 7. 확인 방법

`db/sync_error_test.sql`을 실행하면 오류 유형 6가지가 테스트 로그로 들어간다.

```
1. DB 필수값 누락
2. 스키마 불일치
3. 외부 서버 HTML 오류 페이지 (원문이 길다)
4. 응답 시간 초과 (PARTIAL)
5. 응답 형식 오류
6. 대응표에 없는 예외
```

**확인할 것**

- 오류 내용 칸에 한글 요약이 뜨는가
- 빨간 '오류' 버튼이 눌리는가
- 모달에서 '원문 보기'를 누르면 원문이 나오는가
- 3번처럼 긴 HTML도 회색 박스 안에서만 스크롤되는가
- 대시보드 최근 5건에도 한글 요약이 뜨는가

**확인이 끝나면 파일 아래의 삭제 문장을 반드시 실행한다.** 안 지우면 통계 카드의 '실패' 숫자가 커져 오해를 산다.

```sql
DELETE FROM sync_log WHERE duration_ms = 9999;
```

## 8. 백엔드 변경 요약

| 파일 | 무엇 |
| --- | --- |
| `AdminBenefitSearchReqDto` | `sort` · `order` 필드 추가 |
| `AdminMapper` | `findBenefitList`의 `ORDER BY`를 `<choose>`로 분기 |
| `AdminController` | `getBenefits`에 `@RequestParam sort` · `order` 추가 |

**정렬 값을 SQL에 문자열로 이어붙이지 않는다.** 화면에서 아무 값이나 보낼 수 있으므로, 허용한 값만 `<when>`으로 분기하고 그 밖의 값은 기본 정렬로 떨어뜨린다.

`AdminMapper`는 XML이 아니라 `@Select("<script>...")` 어노테이션 방식이다. `RootConfig`가 `benefit`·`engine` 경로의 XML만 등록하기 때문이다. **고친 뒤에는 서버를 완전히 재시작해야 반영된다.**
